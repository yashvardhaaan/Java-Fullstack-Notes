# Memory Management — GATE CSE 2027

## 1. What is Memory Management?

**Memory management** is the OS function responsible for managing the allocation and deallocation of main memory among processes.

> Main goal: efficiently map **process address space → physical memory** while providing protection and efficient utilization.

---

# 2. Logical vs Physical Address ⭐⭐⭐⭐⭐

### Logical / Virtual Address

Address generated by the CPU.

### Physical Address

Actual address in main memory (RAM).

```text id="5z6m1h"
CPU
 ↓
Logical Address
 ↓
MMU
 ↓
Physical Address
 ↓
RAM
```

### MMU

**Memory Management Unit (MMU)** translates logical/virtual addresses into physical addresses.

$$
\boxed{Logical\ Address \xrightarrow{MMU} Physical\ Address}
$$

---

# 3. Address Binding ⭐⭐⭐⭐

Address binding means mapping program instructions/data to memory addresses.

It can happen at:

### Compile Time

Physical location known at compilation.

### Load Time

Binding performed when program is loaded.

### Execution Time

Binding can occur during execution.

Modern systems commonly use:

$$
\boxed{\text{Execution-time binding}}
$$

because virtual memory and dynamic relocation require it.

---

# 4. Relocation

A program may be loaded at different physical memory locations.

Therefore, the OS/hardware needs to translate addresses appropriately.

Example:

```text id="6t8y1j"
Logical address = 100

Base = 5000

Physical address = 5000 + 100
                 = 5100
```

---

# 5. Base and Limit Registers ⭐⭐⭐⭐⭐

A simple contiguous-memory protection mechanism uses:

### Base register

Starting physical address of the process.

### Limit register

Size/range of the process's logical address space.

If:

$$
0\leq LA<Limit
$$

then:

$$
\boxed{PA=Base+LA}
$$

Otherwise:

$$
\boxed{\text{Address violation}}
$$

---

# 6. Example

Suppose:

```text id="g1yd6b"
Base = 4000
Limit = 1000
```

Logical address:

$$
LA=500
$$

Since:

$$
500<1000
$$

valid.

Physical:

$$
PA=4000+500
$$

$$
\boxed{4500}
$$

If:

$$
LA=1200
$$

then:

$$
1200>1000
$$

so:

$$
\boxed{\text{Invalid access}}
$$

---

# 7. Contiguous Memory Allocation ⭐⭐⭐⭐⭐

In contiguous allocation, a process occupies **one contiguous region** of physical memory.

```text id="g30nqy"
+----------------+
| OS             |
+----------------+
| Process P1     |
+----------------+
| Process P2     |
+----------------+
| Free            |
+----------------+
```

### Advantages

* Simple
* Fast address translation

### Major problem

$$
\boxed{\text{External Fragmentation}}
$$

---

# 8. Partitioning

Two major approaches:

### Fixed Partitioning

Memory divided into fixed-size partitions.

```text id="7pmx5n"
Partition 1
Partition 2
Partition 3
...
```

### Variable/Dynamic Partitioning

Partitions are created according to process size.

```text id="v0x3t9"
P1 → size 100
P2 → size 250
P3 → size 120
```

---

# 9. Internal Fragmentation ⭐⭐⭐⭐⭐

Memory allocated to a process is larger than what it actually needs.

Unused space **inside an allocated block**.

Example:

```text id="7klm0a"
Partition = 100 KB
Process   = 80 KB

Unused = 20 KB
```

$$
\boxed{\text{Internal Fragmentation}=20KB}
$$

### Memory trick

> **Inside allocated block = Internal**

---

# 10. External Fragmentation ⭐⭐⭐⭐⭐

Free memory exists, but it is divided into many small non-contiguous holes.

Example:

```text id="q3r9xx"
P1 | Hole | P2 | Hole | P3 | Hole
```

Total free memory might be enough, but no **single contiguous block** is large enough.

### Memory trick

> **Outside allocated blocks = External**

---

# 11. Internal vs External Fragmentation

| Internal                          | External                                        |
| --------------------------------- | ----------------------------------------------- |
| Waste inside allocated block      | Free space outside allocated blocks             |
| Common with fixed-size allocation | Common with variable-size contiguous allocation |
| Allocated but unused              | Free but fragmented                             |
| Example: page partially unused    | Many small holes                                |

### 🔥 GATE Trap

> External fragmentation means total free memory is insufficient.

❌ Not necessarily.

Total free memory can be sufficient but scattered.

---

# 12. Dynamic Partition Allocation ⭐⭐⭐⭐⭐

When a process needs memory, the OS chooses a suitable free hole.

Major algorithms:

1. First Fit
2. Best Fit
3. Worst Fit
4. Next Fit

---

# 13. First Fit

Choose the **first hole large enough**.

Example:

```text id="3a9r0j"
Holes:
100, 500, 200, 300

Request = 180
```

First suitable hole:

$$
500
$$

Allocate there.

### Shortcut

$$
\boxed{\text{First Fit = first possible}}
$$

---

# 14. Best Fit

Choose the **smallest hole that can satisfy the request**.

Same example:

```text id="qk1x3w"
Holes:
100, 500, 200, 300

Request = 180
```

Suitable:

```text id="gq2t5h"
500, 200, 300
```

Smallest:

$$
\boxed{200}
$$

### Shortcut

$$
\boxed{\text{Best Fit = smallest sufficient}}
$$

---

# 15. Worst Fit

Choose the **largest available hole**.

Example:

```text id="1pxx0r"
Holes:
100, 500, 200, 300

Request = 180
```

Largest:

$$
\boxed{500}
$$

### Shortcut

$$
\boxed{\text{Worst Fit = largest hole}}
$$

---

# 16. Next Fit

Similar to First Fit, but search starts from the location where the **previous search ended**, rather than from the beginning each time.

### 🔥 GATE Trap

```text id="qzyqwr"
First Fit → starts from beginning
Next Fit  → continues from previous position
```

---

# 17. Allocation Algorithm Example ⭐⭐⭐⭐⭐

Holes:

```text id="4q0v8m"
100 KB
500 KB
200 KB
300 KB
600 KB
```

Requests:

```text id="v0eq2a"
212 KB
417 KB
112 KB
426 KB
```

For **First Fit**:

### 212

First sufficient:

$$
500
$$

Remaining:

$$
500-212=288
$$

### 417

Next suitable:

$$
600
$$

Remaining:

$$
600-417=183
$$

Continue similarly.

### 🔥 GATE Method

After every allocation:

> **Update the hole sizes immediately.**

Do not reuse the original hole sizes.

---

# 18. Paging ⭐⭐⭐⭐⭐

Paging divides:

### Logical memory

into fixed-size:

$$
\boxed{\text{Pages}}
$$

### Physical memory

into fixed-size:

$$
\boxed{\text{Frames}}
$$

And:

$$
\boxed{Page\ Size = Frame\ Size}
$$

---

# 19. Page Table

The OS maintains a **page table** that maps:

$$
\boxed{\text{Page number} \rightarrow \text{Frame number}}
$$

Example:

```text id="q25xwm"
Page 0 → Frame 5
Page 1 → Frame 2
Page 2 → Frame 8
```

Pages of a process don't need to occupy contiguous physical frames.

---

# 20. Logical Address in Paging ⭐⭐⭐⭐⭐

Logical address is divided into:

```text id="2l9p8s"
+----------------+--------------+
| Page Number    | Offset       |
+----------------+--------------+
```

If:

$$
Page\ Size=2^p
$$

then:

$$
\boxed{\text{Offset bits}=p}
$$

If virtual address size is \(n\) bits:

$$
\boxed{\text{Page number bits}=n-p}
$$

---

# 21. Paging Address Translation

Suppose:

```text id="q5u7y0"
Page number = 3
Offset = 100
```

Page table:

```text id="z8c4f2"
Page 3 → Frame 7
```

Then:

```text id="9xg8v1"
Physical address
= Frame 7 + Offset 100
```

More precisely:

$$
\boxed{PA=Frame\ Number\times Frame\ Size+Offset}
$$

---

# 22. Paging Numerical ⭐⭐⭐⭐⭐

Virtual address:

$$
16\text{ bits}
$$

Page size:

$$
256\ bytes=2^8
$$

Therefore:

$$
\boxed{Offset=8\ bits}
$$

Page number:

$$
16-8=8\ bits
$$

Number of virtual pages:

$$
2^8=\boxed{256}
$$

---

# 23. Number of Frames

Suppose physical memory:

$$
1MB=2^{20}\ bytes
$$

Page/frame size:

$$
4KB=2^{12}
$$

Number of frames:

$$
\frac{2^{20}}{2^{12}}
$$

$$
\boxed{2^8=256}
$$

---

# 24. Page Size Trade-off ⭐⭐⭐⭐⭐

### Larger page size

Advantages:

* smaller page table
* fewer page table entries
* better transfer efficiency in some cases

Disadvantages:

* more internal fragmentation
* potentially more wasted memory per process

### Smaller page size

Advantages:

* less internal fragmentation

Disadvantages:

* larger page table

### 🔥 GATE Rule

```text id="xyr4oj"
Page size ↑
→ page table size ↓
→ internal fragmentation ↑
```

Generally.

---

# 25. Paging and Fragmentation

Paging eliminates:

$$
\boxed{\text{External Fragmentation}}
$$

because pages can be placed in any free frames.

But paging can have:

$$
\boxed{\text{Internal Fragmentation}}
$$

especially in the last page of a process.

---

# 26. Segmentation ⭐⭐⭐⭐⭐

Segmentation divides a program according to **logical units**.

Examples:

```text id="t5x3j0"
Code
Data
Stack
Heap
```

Each segment can have a different size.

Logical address:

```text id="h1z3mc"
<segment number, offset>
```

---

# 27. Segment Table

Each segment has:

```text id="ppp6m3"
Base
Limit
```

Translation:

If:

$$
offset < limit
$$

then:

$$
\boxed{PA=base+offset}
$$

Otherwise:

$$
\boxed{\text{Segment violation}}
$$

---

# 28. Paging vs Segmentation ⭐⭐⭐⭐⭐

| Paging                          | Segmentation                    |
| ------------------------------- | ------------------------------- |
| Fixed-size units                | Variable-size units             |
| Pages                           | Segments                        |
| Physical-oriented               | Logical/program-oriented        |
| No external fragmentation       | External fragmentation possible |
| Internal fragmentation possible | External fragmentation possible |
| Address = page + offset         | Address = segment + offset      |

### 🔥 GATE Shortcut

```text id="0u3u7c"
Paging → fixed
Segmentation → variable/logical
```

---

# 29. Segmentation Example

Suppose:

```text id="gq7x5p"
Segment 2:
Base = 5000
Limit = 1000
```

Logical address:

```text id="v4t0u7"
<2, 300>
```

Since:

$$
300<1000
$$

valid.

Physical:

$$
5000+300
$$

$$
\boxed{5300}
$$

If offset = 1200:

$$
1200>1000
$$

→ invalid.

---

# 30. Fragmentation Comparison ⭐⭐⭐⭐⭐

| Technique             | Internal |                           External |
| --------------------- | -------: | ---------------------------------: |
| Fixed partitioning    |        ✅ |                   ❌/less prominent |
| Variable partitioning |   ❌/less |                                  ✅ |
| Paging                |        ✅ |                                  ❌ |
| Segmentation          |   ❌/less |                                  ✅ |
| Segmentation + Paging | Possible | Reduced/eliminated at paging level |

---

# 31. Compaction ⭐⭐⭐⭐

Compaction moves allocated blocks to combine scattered holes into one large contiguous hole.

Before:

```text id="16r4fc"
P1 | H | P2 | H | P3 | H
```

After:

```text id="n4c1ps"
P1 | P2 | P3 |       BIG H
```

Purpose:

$$
\boxed{\text{Reduce external fragmentation}}
$$

### Problem

Compaction requires moving data and can be expensive.

---

# 32. Swapping ⭐⭐⭐⭐

A process can temporarily be moved:

```text id="e8v6cg"
RAM ↔ Disk
```

Example:

```text id="4wq6dj"
RAM
 ↓
Swap out
 ↓
Disk

Disk
 ↓
Swap in
 ↓
RAM
```

### Purpose

Free physical memory and support multiprogramming.

---

# 33. Memory Protection

OS must prevent one process from illegally accessing another process's memory.

Examples:

```text id="r4e0o1"
Base/Limit registers
Page-table protection bits
Segment permissions
```

Typical page permissions:

```text id="n7q0d8"
Read
Write
Execute
```

---

# 34. Shared Pages

Paging can allow multiple processes to map a physical frame into their address spaces.

Useful for:

* shared libraries
* shared memory
* memory-efficient code sharing

Example:

```text id="m6w4as"
P1 ──┐
     ├──→ Physical Frame
P2 ──┘
```

---

# 35. Copy-on-Write

After `fork()`:

```text id="5t0z1j"
Parent ──┐
         ├── same physical pages initially
Child  ──┘
```

If one modifies a shared page:

```text id="e9j7q3"
Copy page
   ↓
Separate physical pages
```

This reduces unnecessary copying.

---

# 36. GATE PYQ Pattern — Address Translation

Given:

```text id="f3j7me"
Logical address = page number + offset
```

and a page table:

```text id="r9f7s5"
Page 4 → Frame 7
```

If offset is \(50\):

$$
PA=7\times PageSize+50
$$

### 🔥 Always remember

You cannot calculate physical address from frame number alone.

You also need the **offset**.

# 38. GATE PYQ Pattern — Page Table Size

Suppose:

```text id="i8f1yp"
Virtual address = 32 bits
Page size = 4 KB
PTE size = 4 bytes
```

Page number bits:

$$
32-12=20
$$

Number of entries:

$$
2^{20}
$$

Page table size:

$$
2^{20}\times4
$$

$$
=2^{22}
$$

$$
\boxed{4MB}
$$

### 🔥 Formula

$$
\boxed{
Page\ Table\ Size=
Number\ of\ Pages\times PTE\ Size
}
$$

# 39. GATE PYQ Pattern — Internal Fragmentation

Suppose page size:

$$
4KB
$$

Process size:

$$
10KB
$$

Pages required:

$$
\left\lceil\frac{10}{4}\right\rceil=3
$$

Allocated:

$$
3\times4=12KB
$$

Internal fragmentation:

$$
12-10
=
\boxed{2KB}
$$

# 🔥 GATE Traps

### Trap 1

> Paging causes external fragmentation.

❌ Standard paging eliminates external fragmentation.

---

### Trap 2

> Paging has no fragmentation.

❌ Paging can cause internal fragmentation.

---

### Trap 3

> Segmentation has no fragmentation.

❌ Segmentation can cause external fragmentation.

---

### Trap 4

> Page size = frame size is optional.

❌ They must be equal for standard paging.

---

### Trap 5

> Logical address = physical address.

❌ MMU translates logical → physical.

---

### Trap 6

> Larger pages always improve memory efficiency.

❌ Larger pages generally increase internal fragmentation.

---

### Trap 7

> Best Fit means largest available hole.

❌

```text id="u9h7z6"
Best Fit  → smallest sufficient
Worst Fit → largest
```

---

### Trap 8

> First Fit and Next Fit are identical.

❌ Next Fit continues from the previous search position.

---

### Trap 9

> External fragmentation means memory is insufficient.

❌ Total free memory may be sufficient but scattered.

---

### Trap 10

> Context switch and address translation are unrelated to protection.

Memory management handles address translation/protection; scheduling handles CPU allocation.
