# HMAC — Hash-Based Message Authentication Code

## 1. First Principle

**HMAC combines a cryptographic hash function with a secret key.**

Its main purpose is to provide:

```text
Integrity
+
Authentication
```

Mental model:

```text
Message + Secret Key
        ↓
       HMAC
        ↓
Authentication Tag
```

If the message changes, the HMAC verification should fail.

---

# 2. Hash vs HMAC

A normal hash:

```text
SHA-256(message)
```

does **not** prove who created the message.

Anyone can calculate the hash.

HMAC:

```text
HMAC(secret_key, message)
```

requires knowledge of the secret key.

Therefore:

```text
Hash
→ Integrity/fingerprint

HMAC
→ Integrity + authentication
```

---

# 3. How HMAC Works

Sender:

```text
Message
   +
Secret Key
   ↓
HMAC
   ↓
HMAC Tag
```

The sender sends:

```text
Message + HMAC Tag
```

Receiver has the same secret key:

```text
Received Message
       +
Secret Key
       ↓
Calculate HMAC
       ↓
Compare with received tag
```

If they match:

```text
Valid ✓
```

If they don't:

```text
Invalid ✗
```

---

# 4. HMAC Does NOT Encrypt Data

This is an important distinction.

```text
HMAC
→ Does not hide the message
```

Example:

```text
Message:
"Transfer ₹5000"

HMAC:
"a81f92..."
```

The message is still visible unless encryption is also used.

For confidentiality + integrity:

```text
Encryption
+
Authentication
```

or preferably an authenticated-encryption scheme such as AES-GCM.

---

# 5. HMAC Algorithms

Common combinations include:

```text
HMAC-SHA256
HMAC-SHA384
HMAC-SHA512
```

A common modern choice:

```text
HMAC-SHA256
```

---

# 6. Industry Example — API Authentication

Suppose a payment API needs to verify that a request was generated by an authorized client.

Request:

```text
POST /payment
amount=5000
```

The client has a secret API key.

Conceptually:

```text
Request Data
    +
API Secret
    ↓
HMAC-SHA256
    ↓
Signature
```

The server independently calculates the HMAC.

```text
Client HMAC == Server HMAC
        ↓
       ✓
```

The request can proceed.

---

# 7. Preventing Request Tampering

Suppose an attacker intercepts:

```text
amount=5000
```

and changes it to:

```text
amount=50000
```

The original HMAC no longer matches.

```text
Modified Request
       ↓
HMAC verification
       ↓
Invalid ✗
```

The server can reject it.

**Important:** HMAC does not by itself prevent replay attacks.

---

# 8. Replay Attacks

An attacker could capture a legitimate request:

```text
Request + Valid HMAC
```

and send the exact same request again.

The HMAC may still be valid.

A common defense is to include:

```text
Timestamp
+
Nonce
+
Request Data
```

inside the authenticated data.

Example:

```text
timestamp=2026-10-13T15:00
nonce=abc123
amount=5000
```

Then:

```text
HMAC(secret, timestamp + nonce + request)
```

The server can reject:

- Expired timestamps
- Previously used nonces

---

# 9. HMAC in Webhooks

A very common industry use case is **webhook verification**.

Suppose a payment provider sends:

```text
POST /webhook
```

with:

```text
payment_status=success
```

The provider calculates:

```text
HMAC(secret, request_body)
```

and sends the result in a header.

Your application:

```text
Receive webhook
      ↓
Read signature
      ↓
Calculate HMAC
      ↓
Compare signatures
      ↓
Valid?
```

Only then should the application trust the webhook.

---

# 10. HMAC vs Digital Signature

| HMAC | Digital Signature |
|---|---|
| Symmetric | Asymmetric |
| Shared secret | Private/public key |
| Both sides know secret | Private key remains with signer |
| Fast | Generally more computationally expensive |
| API/webhook authentication | Certificates/code/document signing |
| No public verification | Anyone with public key can verify |

Mental model:

```text
HMAC
→ "We both know the secret."

Digital Signature
→ "This was signed by the holder of this private key."
```

---

# 11. HMAC vs Hash

```text
Hash:

SHA256(message)
```

Anyone can calculate it.

```text
HMAC:

HMAC(secret, message)
```

Only someone possessing the secret can generate a valid HMAC.

Therefore:

```text
Hash ≠ Authentication
HMAC = Authentication + Integrity
```

---

# 12. HMAC vs AES-GCM

Both can provide integrity/authentication, but they serve different purposes.

```text
AES-GCM
→ Encryption + authentication

HMAC
→ Authentication/integrity only
```

For example:

```text
Sensitive API payload
      ↓
AES-GCM
      ↓
Encrypted + authenticated
```

Whereas:

```text
Visible webhook payload
      +
HMAC
      ↓
Authenticity/integrity verification
```

# 13. Small Python Lab

```python
import hmac
import hashlib

secret = b"my-secret-key"
message = b"amount=5000"

signature = hmac.new(
    secret,
    message,
    hashlib.sha256
).hexdigest()

print(signature)
```

Verify it:

```python
expected = hmac.new(
    secret,
    message,
    hashlib.sha256
).hexdigest()

print(hmac.compare_digest(signature, expected))
```

Output:

```text
True
```

Now change the message:

```python
message = b"amount=50000"
```

Verification should fail.

---

# 14. Why `compare_digest()`?

Don't casually compare security-sensitive signatures using ordinary string comparison.

Prefer:

```python
hmac.compare_digest(a, b)
```

It is designed for safer comparison of secrets/tags and helps reduce timing side-channel risks.

# 17. Common Mistakes

### ❌ Using plain hashes for authentication

```text
SHA256(message)
```

doesn't prove who generated the message.

### ❌ Hardcoding HMAC secrets

```java
String secret = "super-secret"; // ❌
```

Use proper secret management.

### ❌ Ignoring replay protection

Use timestamps/nonces where the protocol requires it.

### ❌ Logging HMAC secrets

Never put secrets into application logs.

### ❌ Comparing signatures carelessly

Use a safe comparison function such as:

```python
hmac.compare_digest()
```

# 18. Interview Questions

### Q1. What is HMAC?

A keyed construction combining a secret key with a cryptographic hash to provide message integrity and authentication.

### Q2. Does HMAC encrypt data?

No.

### Q3. HMAC vs SHA-256?

```text
SHA-256(message)
→ Hash

HMAC-SHA256(secret, message)
→ Keyed authentication/integrity
```

### Q4. Where is HMAC commonly used?

APIs, webhooks, signed requests, and authentication protocols.

### Q5. Can HMAC prevent replay attacks?

Not by itself.

Use mechanisms such as:

```text
Timestamp
Nonce
Sequence number
```

### Q6. HMAC vs digital signature?

HMAC uses a shared secret; digital signatures use a private/public key pair.
