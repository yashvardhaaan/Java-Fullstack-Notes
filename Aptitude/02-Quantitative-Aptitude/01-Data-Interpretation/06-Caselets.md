# Caselets

## Definition

A **Caselet** is a paragraph or scenario containing numerical and logical information instead of a graph or table. The information is usually presented in text form, and you must organize the data yourself before solving the questions.

Unlike other Data Interpretation questions, Caselets require both **reading comprehension** and **data analysis**.

---

# Why Learn This?

Caselets simulate real-world situations where data is rarely presented in neat tables or charts.

Applications include:

- **Business Analysis** – Understanding business reports, financial summaries, and project updates.
- **Software Engineering** – Analyzing application logs, system reports, and performance summaries.
- **Data Analytics** – Extracting useful information from textual reports before visualization.
- **Finance** – Reading annual reports, investment summaries, and financial statements.
- **Healthcare** – Interpreting patient records, clinical reports, and research findings.
- **Management** – Making decisions based on project reports and operational updates.

# Characteristics of Caselets

- Information is given in paragraph form.
- Data may not be arranged systematically.
- Some information may be unnecessary.
- Multiple questions are asked from a single passage.
- Requires converting text into tables or lists.

# Best Practices

### 1. Create Your Own Table

Convert paragraph data into rows and columns.

Example

Instead of reading:

```
A sold 120 units,
B sold 150 units,
C sold 180 units.
```

Write

| Product | Units |
|---------|------:|
| A | 120 |
| B | 150 |
| C | 180 |

This reduces mistakes.

---

### 2. Highlight Numbers

Circle or underline:

- Totals
- Percentages
- Ratios
- Dates
- Years

---

### 3. Solve Questions One by One

Do not perform unnecessary calculations.

---

### 4. Ignore Irrelevant Information

Some statements are intentionally included to distract you.

---

### 5. Use Intermediate Calculations

For lengthy problems, write intermediate values before proceeding.

# Solved Example

A company has four departments.

- IT has **80** employees.
- HR has **40** employees.
- Sales has **60** employees.
- Finance has **20** employees.

---

## Example 1

Find the total employees.

Solution

```
80 + 40 + 60 + 20

=200
```

Answer

```
200
```

---

## Example 2

Find the average employees.

Solution

```
200 / 4

=50
```

Answer

```
50
```

---

## Example 3

Find the percentage of IT employees.

Solution

```
(80/200)×100

=40%
```

Answer

```
40%
```

---

## Example 4

Find the ratio of Sales to Finance.

Solution

```
60 : 20

=3 : 1
```

Answer

```
3 : 1
```

# Practice Questions

A startup has four teams.

- Backend = 25 employees
- Frontend = 20 employees
- QA = 15 employees
- DevOps = 10 employees

---

## Q1

Find the total employees.

**Answer**

```
25 + 20 + 15 + 10

=70
```

---

## Q2

Find the average employees per team.

**Answer**

```
70 / 4

=17.5
```

---

## Q3

What percentage of employees work in Backend?

**Answer**

```
(25/70)×100

≈35.71%
```

---

## Q4

Find the ratio of Frontend to DevOps.

**Answer**

```
20 : 10

=2 : 1
```

---

## Q5

How many more employees work in Backend than QA?

**Answer**

```
25 − 15

=10
```

# GATE 80/20 Summary

✅ Read the **entire caselet first** before solving.

✅ Convert paragraph data into a **table** whenever possible.

✅ Highlight important numbers and ignore unnecessary information.

✅ Most questions involve **total, average, percentage, ratio, and comparison**.

✅ Organizing the data correctly is often more important than the calculations.
